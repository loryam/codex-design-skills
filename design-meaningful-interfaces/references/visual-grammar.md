# Visual Grammar for Meaningful Interfaces

Use this reference while composing or critiquing a screen. Choose patterns because they communicate product meaning, not because they are fashionable.

## 1. Meaning Map

| Product meaning | Useful visual treatment | Avoid |
| --- | --- | --- |
| Current answer | Dominant hero card, large value, concise descriptor | Burying the answer under instructions |
| Active process | Distinct tinted status panel, live indicator, manage action | Mixing live state into historical text |
| Progress | Ring, bar, stepped timeline, or restrained trend | Decorative charts with no decision value |
| Adaptation | Previous-vs-current comparison, delta, reason list | Claiming personalization without showing change |
| History | Timeline, grouped activity, trend, recent highlights | Long undifferentiated event lists |
| User input | Compact pills, segmented controls, focused form | Large repeated explanatory blocks |
| Warning | Clear contrast, specific consequence, repair action | Alarm color everywhere |
| Premium preview | Concrete outcomes and comparison | Checkout theatre before billing exists |
| Empty state | One useful explanation and next action | Empty panels that look broken |

## 2. Screen Narrative Patterns

### Decision screen

Use for routines, recommendations, eligibility, and next-step planning.

1. Recommendation hero
2. Reasons or evidence
3. Previous-vs-current change
4. Next available path
5. Quiet safety or support note

### Daily memory screen

Use for activity, wellness, exposure, finance, or habit summaries.

1. Daily summary hero
2. Three or fewer compact signals
3. Visual rhythm or timeline
4. Live status panel when tracking is active
5. Focused check-in
6. Next insight

### Operational status screen

Use for permissions, background work, sync, setup, or reliability.

1. Current status
2. Why it matters
3. Repair action
4. Optional technical detail

### Upgrade preview

Use before a purchase system exists or when explaining paid value.

1. Outcome-led hero
2. Three differentiated paid-value cards
3. Free-vs-paid comparison
4. Explicit free-tier reassurance
5. Honest interest or purchase action

## 3. Hierarchy Heuristics

- Give the primary answer the largest visual weight.
- Limit the first viewport to one dominant object and a small number of supporting signals.
- Make sections visually different when their jobs differ.
- Use repetition for comparable data, not for unrelated content.
- Use whitespace to separate decisions.
- Place repair actions near blocked states.
- Keep explanation one level below the state it explains.

## 4. Responsive Translation

Preserve meaning while adapting layout.

### Small mobile

- Stack narrative sections vertically.
- Keep one clear anchor per viewport.
- Use horizontal scroll only for naturally sequenced evidence.
- Keep touch targets at least platform minimum size.

### Tablet and desktop web

- Use a two-column composition when it improves scanning.
- Keep the primary answer and live state in the stronger column.
- Place evidence, comparisons, or secondary controls in the supporting column.
- Avoid stretching mobile cards into excessively wide text blocks.

## 5. State Vocabulary

Design states as first-class interface variants:

- Default
- Active
- Paused
- Empty
- Loading
- Success
- Blocked
- Warning
- Recovery
- Premium preview

For each state, change at least one meaningful signal: headline, icon, tint, action, data visualization, or section visibility. Do not rely on paragraph copy alone.

## 6. Critique Test

Blur or skim the screen mentally. Ask:

- Where does the eye land first?
- Is that the correct answer?
- Which elements communicate state without reading?
- Are any cards merely containers for prose?
- Is there a clear next action?
- Does the UI reveal product intelligence through comparison, evidence, or consequence?

Revise until the design speaks before the explanation begins.
